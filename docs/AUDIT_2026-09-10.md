## 1. Bottom line

The product is real and running: 104 of 159 parishes harvested for the week of 06/09/2026, four diocese viewers live with the mega PDF, OCR and search, panels locked 850px desktop / 450px phone (measured live today), Trainer 1.61.24 zip installs. **Overall mark: 66 / 100.**

The three things holding it back are not features, they are honesty gaps:

1. **The site can label last week's bulletin as this week.** Live proof: `/parishes/raphoe/ardara.html` says "bulletin for Ardara — 06/09/2026" and serves a PDF, while `parish_status.json` says Ardara is `stale` (bulletin 30/08) and Ardara is not in this week's Raphoe mega. No stale note on the page.
2. **`parish_status.json` cannot prove "this week".** All 104 `ok` rows have no bulletin date field; `last_tested_at` is empty on all 159 rows. So "ok = this week" is an assumption, not a recorded fact. 8 live recipes have no row at all (invisible to the Problems tab).
3. **CI cannot fail on the things the rules care about.** No `node --check` on extension JS (the 1.61.23 crash would have been caught). `ocr-bulletin.yml` commit step has `continue-on-error: true` (forbidden by AGENTS.md). Harvest tests are `continue-on-error`. No test asserts 850/450 on generated HTML.

Everything else is polish, dead code, and 20+ stale markdown files that contradict each other.
